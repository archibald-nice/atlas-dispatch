# Atlas 管理者手册

**第一次接手：在项目目录运行 `npm run release -- status`。** 它只读本地文件：告诉你当前版、上一个启用版、应该打开的 HTML，以及当前版对应的 Git 提交和快照指纹。若无当前版，按下方「建立首个本地版本」操作。

Atlas 是**打包后可直接打开的离线资讯地图**，不是后台服务。管理者手动采集、核对并启用一版；读者打开该版 HTML，不会触发采集。下载旧文件的读者不会自动收到新版。点「原文」需要联网。

## 先认清三个东西

| 你在管什么 | 到哪里找 | 不要混用 |
| --- | --- | --- |
| 代码和采集规则 | Git；[`scripts/sources.json`](../scripts/sources.json) 是信源清单；[`scripts/adapters.mjs`](../scripts/adapters.mjs) 是解析器 | 改规则后先验证、提交，再准备管理版。Git 的提交记录不等于内容上线。 |
| 资讯快照 | `releases/versions/<版本号>/snapshot.json` 是该版本实际使用的数据；[`src/data/snapshot.json`](../src/data/snapshot.json) 是随源码提供的工作快照 | 工作快照不是当前启用版；不手改版本包。要修编辑标题、摘要或要点，改 [`editorial-overrides.json`](../src/data/editorial-overrides.json) 后重采对应信源。 |
| 给人打开的页面 | `npm run release -- status` 给出当前 `releases/versions/…/index.html`；`dist/index.html` 是 `npm run build` 的临时预览 | 准备候选不会切换当前版；不要把开发预览、源代码目录或本地版本目录直接发给读者。 |

从实现看，只需理解三层：采集器通过清单发起有限 HTTPS 请求，解析并校验快照；本地出包器用同一份快照构建并记录校验和；浏览器打开 HTML，由 `src/App.tsx` 管筛选与阅读，`src/scene/` 负责地球渲染。浏览器没有服务端或数据库依赖。

## 建立首个本地版本

需要 Git、Node.js 22.18+ 和支持 WebGL2 的浏览器。新工作目录首次安装依赖用 `npm ci --ignore-scripts`。受管理的出包要求构建相关源码已提交；临时测试未提交的改动用 `npm run build`。

1. 运行 `npm run release -- prepare`。首次用仓库自带的工作快照，不联网；有当前版时复用当前版快照，适合只发代码修复。
2. 按终端打印的路径打开候选 `index.html`。确认能离线打开，随机核对一条记录的来源、时间和原文链接；涉及地区的变更再核对事件地点与机构／主体关联。
3. 复制终端打印的 `npm run release -- activate <版本号>` 执行。启用是本地动作，不会上传；用 `status` 确认当前版和打开路径。

## 日常更新与异常处理

1. **准备候选：** `npm run update` 采集全部信源；只更新 NASA 用 `npm run release -- prepare --source nasa`。二者从当前启用版派生，首次没有启用版时才用工作快照做底。`npm run sources:list` 查看信源 ID。
2. **检查变化：** `npm run release -- report <版本号>`。检查新增、移除、有改动、失败沿用、未变，以及各源最近成功与尝试时间。按每个信源内的稳定事件 ID 比较；总数不变也可能整批换了。
3. **决定启用：** 预览通过后执行打印的启用命令。信源采集失败、一个信源从候选中消失，或原有至少 4 条且成功后降至一半或更少，会要求人工确认。先检查原始信源、更新窗口和解析规则；有合理解释才用 `npm run release -- activate <版本号> --accept-warnings "原因"`。不确定就保持当前版，不靠重复刷新把异常刷掉。

| 遇到什么 | 怎么处置 |
| --- | --- |
| 采集全失败、校验失败或构建报错 | 不启用；运行 `status` 确认仍是旧版，再按报错排查。不删旧版本目录。部分源失败时，检查该源是沿用旧数据还是没有旧数据。 |
| 说候选基准过期 | 有其他候选先启用，或当前版被回退了。重新准备、比较和预览，不能跳过。 |
| 刚启用的版本有问题 | `npm run release -- rollback`，然后打开命令打印的旧版本 HTML。回退不联网、不重新打包，也不修改 Git 或工作快照；再次执行会在这两个已启用版本之间切换。 |
| 报校验和失败 | 不手写 `current.json`，也不修补版本里的 HTML。若上个启用版完好，先 `rollback`；否则用备份恢复原件再校验。 |
| 版本指针被锁定 | 不并行跑启用或回退。若确认写入进程已退出且锁残留，只移除空的 `releases/.state-lock` 目录，不动 `current.json` 或版本文件。 |

`npm run refresh [-- --source <ID>]` 仅供研究采集结果，会写工作快照，不改当前版。确需用该快照创建候选时，用 `npm run release -- prepare --working-snapshot`。不要把它当日常更新路径。

## 备份与对外准备

- **备份两部分：** Git 保管源码，`releases/` 保管实际版本。后者不进 Git；至少备份 `current.json`、它引用的两个完整版本目录，以及每版 `manifest.json`。恢复时把它们放回同一结构，运行 `status` 校验。系统不会自动清理历史；磁盘维护先核对引用和备份。
- **追溯一版：** 打开其 `manifest.json`，查 `gitCommit`、`nodeVersion`、`comparedTo`、快照生成时间及各文件 SHA-256。SHA-256 校验文件一致性，不是签名。出包要求干净代码，但不承诺跨系统字节级可复现；请使用锁定依赖。
- **公开前只用受限候选：** 当前代码与已启用版匹配时，`npm run release -- export` 生成单独的免费审阅候选。它不发布、不授权，也不是付费版。先读 [分发边界](PUBLICATION.md)，私有 Git 历史不能直接转公开。

没有 CI/CD、外部推送、定时采集、用户账号或服务器需要日常维护。开发服务可按 [README](../README.md#开发与验证) 手动启动，但运行任何上述管理命令都不需要它。
